# AWS の片づけ手順

Terraform（Phase 4）で作り直す前に、これまでの作業で残ったものを消す。
**消す前に必ず棚卸しをして、何が動いているかを確かめてから進める。**

所要時間の目安は、棚卸しに10分、確認と削除に30分。

---

## 0. 消してはいけないもの

先にこれを読む。下の4つは、消すとサイトが止まるか、元に戻せない。

| 消さないもの                                | 理由                                                                                                       |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Amplify のアプリ `d3fj0jchd8ri0z`           | **いま imrg.work を配っている本体。** 新しい構成に切り替えて数日たってから消す                             |
| Route53 のホストゾーン `imrg.work`          | 消すとドメインの設定が全部消え、作り直しても**ネームサーバーが変わる**（ドメイン側の登録もやり直しになる） |
| いま使われている証明書                      | 「使用中」の数が 1 以上のものは、CloudFront か Amplify が使っている                                        |
| CloudTrail のログ置き場（0-8 で作ったもの） | 記録を残すために作った。残す                                                                               |

判断に迷ったら消さない。**止めるだけにして数日おく**（Amplifyなら「ブランチの自動ビルドを止める」、
EC2なら「停止」）。問題が出なければ消す。

## 1. 棚卸しをする

読むだけで何も変えないスクリプトを用意してある。

```bash
cd ~/imrg/imrg-platform
./terraform/scripts/aws-audit.sh > ~/aws-audit.txt
open -R ~/aws-audit.txt
```

出力にはアカウントIDが入るので、リポジトリーには入れない（`~/` に置く）。

見るところは次の順番。

1. **「1. 直近3か月の費用」** … お金がかかっているサービスがここに出る。ここに出ないものは、消しても請求は減らない
2. **「11. 使っていないのに料金がかかるもの」** … 外れたままのディスク・割り当てていない固定IP・NATゲートウェイ。
   身に覚えがなければ、まず消してよいもの
3. **「7. IAM ユーザーとアクセスキー」** … 最終使用が「なし」または半年以上前の鍵は、使われていない
4. 残りは、作った覚えがあるかどうかで振り分ける

## 2. 消す順番

依存があるので、この順で進める。逆にすると「使用中」で消せない。

```
Amplify のアプリ（移行後）
  → CloudFront の配信（先に「無効化」してから削除。15分ほどかかる）
    → 証明書（どこからも使われていない状態にしてから）
      → Route53 のレコード（ゾーンは残す）
IAM: 鍵 → ユーザー → ポリシーの切り離し → ポリシー → ロール
S3: 中身を空にする → バケット
```

## 3. よくある残りものと、消し方

### 使っていない IAM のアクセスキー

鍵は漏れると被害が大きい。**使っていないものは必ず消す。**

```bash
# まず「無効」にして数日おく（使われていたらエラーが出るので気づける）
aws iam update-access-key --profile imrg --user-name <ユーザー名> \
  --access-key-id <鍵のID> --status Inactive

# 数日たって問題がなければ消す
aws iam delete-access-key --profile imrg --user-name <ユーザー名> --access-key-id <鍵のID>
```

### 使っていない S3 バケット

古い静的ホスティングやログの置き場が残っていることが多い。
**中身を空にしないと消せない。** 版を有効にしていた場合は古い版も消す必要がある。

```bash
# 中身を確認（消す前に必ず見る）
aws s3 ls s3://<バケット名>/ --profile imrg --recursive --human-readable --summarize | tail -5

# 空にして消す
aws s3 rm s3://<バケット名>/ --profile imrg --recursive
aws s3api delete-bucket --profile imrg --bucket <バケット名>
```

版を有効にしていて消えないときは、コンソールの **バケットを空にする** を使うのが早い。

### 使っていない証明書

`length(InUseBy)` が `0` のものは、どこからも使われていない。
ただし**これから CloudFront で使う `imrg.work` の証明書は消さない**。
Terraformは新しく作り直すものの、検証には時間がかかる。既存のものを取り込んだほうが速い。

```bash
aws acm delete-certificate --profile imrg --region us-east-1 --certificate-arn <ARN>
```

### 保存期間が「なし」の CloudWatch ロググループ

ずっと溜まり続けて少しずつ課金される。消さずに**保存期間を決める**のがよい。

```bash
aws logs put-retention-policy --profile imrg --region ap-northeast-1 \
  --log-group-name <名前> --retention-in-days 30
```

### 古い CloudFront の配信

いきなり消せない。**無効化 → 反映を待つ（15分ほど）→ 削除**の順になる。
コンソールのほうが手順は短い。配信を選んで「無効化」し、状態が `Deployed` に戻ってから「削除」する。

## 4. Amplify を消す（移行が終わってから）

新しい構成に切り替えて数日、問題が出なかったら行う。

1. Amplifyのコンソールで、アプリ `d3fj0jchd8ri0z` の**ブランチの自動ビルドを止める**
2. 1週間おく
3. アプリを削除する
4. リポジトリーの `amplify.yml` を消す（`docs/TODO.md` の6-6もここで済む）
5. GitHubの設定から、Amplifyが付けたwebhookとアプリの連携を外す

## 5. 片づけたあとに確かめる

```bash
# もう一度棚卸しして、消したものが消えているか
./terraform/scripts/aws-audit.sh > ~/aws-audit-after.txt
diff ~/aws-audit.txt ~/aws-audit-after.txt

# サイトが開くか
curl -sI https://imrg.work/ | head -1
```

翌月の請求を見て、狙ったとおり減っているかを確かめる。
